   **TKT-557 class ledger.** Only the four named sites can make the store's named `PreDecisionUnavailable` type; the API never classifies a raw error. 503 needs one of: (a) D39 expiry, decided by server-owned phase state (the step timer fired in the pre-decision phase and the parent was alive), never by the driver's error spelling, and winning over a late success, a late no-row (unknown or revoked) read or an unsupported error; (b) a parent deadline before or during the step; (c) a ConnectError whose every branch ends at a DNS error, ECONNREFUSED, or a connect-time PgError 57P03 or 53300, with no unsupported sibling and no rescue by a post-connect class; (d) a proved post-connect class at its proved site: PgError 57P01 at all four sites, io.ErrUnexpectedEOF and ECONNRESET at the two reads, pgconn.ErrConnClosed at the two acquisitions. A parent cancellation is 500 and wins over step expiry. Closed pool, bad connection (`driver.ErrBadConn`), io.EOF, EPIPE, wrong credentials, unknown SQL or configuration, an independent socket timeout before the server bound, a reset or EOF during startup, and statement 57P03/53300 stay 500. Each admitted class has a real producer in the smoke gate, including a real recovery-held PostgreSQL for 57P03. Touch is one autocommit `FOR NO KEY UPDATE SKIP LOCKED` statement under its own PROVISIONAL 500 ms bound and stays advisory.

   **TKT-557 deviation, D21.** The connect-time 57P03/53300 classes qualify only when every connect attempt fails with a supported leaf. With the pgx default `prefer`, a failed TLS attempt adds an untyped child, and the strict rule answers 500. Access therefore refuses any `DATABASE_URL` without an explicit final `sslmode=disable` or with an effective TLS configuration or fallback, in every DB-using command, and the three Compose Access URLs set it. The Compose PostgreSQL has no TLS, so this costs no encryption. It is a Compose-only restriction: a TLS topology needs a new ADR and a new real-driver probe. A DNS failure is availability only inside the Compose premise; outside it a wrong host name can also send scans offline. Test real pgx/database behavior at all sites, including AuthenticateScannerDevice. Its generic-availability-wrap mutation must fail the store test; API stubs prove only the mapper. pgx dial behavior is library knowledge, not verified here. Unclassified errors stay 500. Credential/collision remain 422; policy/admission commit errors and response drift stay 500, P01/P04. Do not give a partly committed R batch a pre-decision 503.

   Add recover outside Access's response and request validators. It answers exact JSON 500 for panic before network headers, including after commit and in the security hook. Test real-store wrapper/handler and security-hook panic, not a response-validator injection that Router does not expose. After network headers, preserve the status and abort the partial body rather than claiming a replacement 500. It does not turn a decided refusal into offline permission. Abrupt kill/shutdown deadline and transport loss still retain U. Require the effective Access and gateway write timeouts each to be at least 30 s, through a startup check or a configuration test plus documented restriction. Cover both processes and Compose overrides; document in `docs/configuration.md` and the operator guide. ReadTimeout does not bound a long handler, section 2.4b. Do not claim that recover or equal write limits remove every response-loss race.

D24's rationale is amended by D34. Main reaches a DB outage first through device lookup; before TKT-557 it emitted 401 there, and since TKT-557 it emits the lookup 503/500, all of which its old client still queues. Terminal 401 plus terminal 500 without the complete ticket-0 device-lookup and scan read/begin split would remove that outage path; keeping 500 offline as on main would turn unknown commits or validator-hidden denials into offline instructions and facts; reading the 500 body would not give a reliable permission contract or identify every producer. The chosen cost is terminal U03 for 500/501/505-599 and possible A, while verified no-response O01/O02 retain U. Unknown proxy production is not admission evidence; the fixed client nevertheless selects O02 for external 502/503/504. A Compose-only ADR premise and qualification before any intermediary deployment are required. Staff can force offline by cutting the network. This is a known workaround, not a guarantee or a replacement for ticket 0.

Direction persistence and version isolation do not logically require an elapsed timer. This design reasoning is **not verified** by implementation here. Owner D13-2 rejects Exit-first delivery because fetch/body/mark can remain late without ticket 3. No alternative Exit-before-time path remains.
