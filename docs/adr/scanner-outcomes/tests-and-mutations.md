### 6. Tests and mutations, by invariant, ADR-085 D11 of TKT-556

Delivery status: each test belongs to the ticket that implements its invariant or row, section 8. TKT-556 did not write or run any of these tests.

The tests below define the full model. TKT-558 implements the untimed Entry/storage subset. TKT-399 delivers the Exit tests; section 3.1 records TKT-559's Entry time delivery. Production store means the real occurrence implementation with `fake-indexeddb`, not an object that returns PENDING or QUEUED as instructed by the test. A controlled owner-lock implementation may enforce the actual exclusion rules deterministically. In addition, test the production browser-lock adapter with controlled Web Locks callbacks, and test genuine cross-page locks in Chrome. A fake store cannot observe ownership.

Ticket 0 has its own producer tests, ADR-085 D34 of TKT-556/ADR-085 D35 of TKT-556/ADR-085 D37 of TKT-556/ADR-085 D39 of TKT-556; TKT-557 shipped them. TKT-558 implements App-500 terminal handling and the untimed Entry/storage ledger subset. Use `Router(log, true)` for every S/R/F API case. Assert exact status, Content-Type and decoded body with no extra or missing fields. The error hook runs outside response validation. API tests with a typed stub prove only the mapper; real-driver classification needs separate store evidence.

- On each route, missing/blank/unknown/revoked token gives 401 and exactly `{"error":"scanner device is not enrolled"}`. Nil device store and unknown auth scheme also stay 401 as configuration/contract faults; no lookup ran. Classified device-store availability gives 503 and exactly `{"error":"scanner device lookup unavailable"}`. Another lookup error gives 500 and exactly `{"error":"scanner device lookup failed"}`. Failing lookups call neither Touch nor a handler/store decision. Use explicit typed errors and the context discriminator, never message matching. Successful lookup calls Touch and continues; Touch failure remains advisory and cannot become pre-decision 503. All no-decision proof covers this HTTP request, not every attempt for the occurrence.
- Use the real pgx driver through the production database adapter and a real database for `AuthenticateScannerDevice`, initial S slot-policy read, and pass/single BeginTx. Ticket 0 must define an explicit class ledger for connection refused, closed pool, bad connection, ADR-085 D39 of TKT-556 deadline expiry and unsupported errors; TKT-557 records it in section 8. State supported typed representations and origins and demonstrate each with the real driver. ADR-085 D39 of TKT-556 expiry is required availability 503; the other supported classes are chosen in that review. Classes without proof stay 500. Do not classify every SELECT/BeginTx failure as availability. Prove no ticket decision or admission write occurred for this HTTP request. An API stub cannot prove the driver classification. pgx dial behavior is not verified here.
- ADR-085 D39 of TKT-556's server deadline bounds the read-only device SELECT, slot-policy read and BeginTx well inside the scanner's literal 3 s send budget. Ticket 0 ships a provisional value; TKT-560 qualifies it. Test expiry at each site with real pgx/database operations; verify bounded completion, typed availability and API 503. Later transaction/commit expiry stays 500. Unclassified read/begin errors stay 500; credential/collision stay 422; policy/admission commit failures stay 500. A partly committed R batch cannot become pre-decision 503. Mutate AuthenticateScannerDevice so availability is wrapped as a generic error; the store test itself must fail. Also mutate expiry classification at each read/begin site. API mapper tests cannot substitute for store-test failures.
- Use a real-store wrapper that calls the production Access store/database and then panics before its Scan wrapper returns to the handler. Cover an actual committed acceptance and an actual decided refusal. Through `Router(log, true)` and production outer recover, assert exact 500 `{"error":"request failed"}`. Re-read the admission for acceptance. For refusal, record the underlying refusal and assert no admission was appended. This proves a decided refusal hidden behind recover 500. Also inject a security-hook panic through the device-store port. Removing outer recovery must fail these API tests. Drop the response-validator panic injection: Router passes `openapi3filter.ValidateResponse` directly at `shared/go/contract/http.go:233`; there is no Router injection point for it.
- Keep validator drift-to-500 separate. Use a named contract-tier test handler, `scannerResponseDriftHandler`, with the Access scan route/spec and production contract validator. It emits an invalid 409 or accepted-200 body with response validation enabled. Assert exact 500 `{"error":"response violates OpenAPI contract"}`. Follow the existing named `driftingHandler` and exact response test at `shared/go/contract/http_test.go:138-148`, `:226-245`. This proves validator substitution, not a real Access decision/commit. The real-store panic tests above provide that decision/commit evidence through recover.
- Test Access and gateway effective write timeouts against the literal 30 s scanner limit. Cover defaults, Compose forwarding and an override below 30 s. Ticket 0 chooses a startup guard or configuration test with documented restrictions. Removing either server's check must fail its own case. The check reduces configuration risk; it removes neither abrupt-loss U nor the race at equality.
- Mutate lookup availability back to 401; each route's API case must fail. Mutate 503 JSON while retaining status; exact-body assertions must fail. For F, explicitly validate the error hook's captured 503 response against the resolved route/spec with `openapi3filter.ValidateResponse` and `IncludeResponseStatus:true`. Assert successful validation; remove the F 503 declaration and require this test to fail for undocumented status. Contract documentation checks alone cannot prove it. Preserve S/R 503 declarations. Mutate App 500 into queue eligibility and remove contract response enforcement; each must fail its own fixture.
- Maintain a route/error-class ledger for status, transport before headers, known-status body loss, local exceptions and transparent resend. Run P13's Chrome probe before stronger per-occurrence claims. Record unverified classes as unverified. Compose-only deployment is an ADR premise; an intermediary requires a new ADR and qualification before deployment, not a client fallback switch.
