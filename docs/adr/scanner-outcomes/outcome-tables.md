#### 3.1 Time and response classification, ADR-085 D5 of TKT-556-ADR-085 D7 of TKT-556 and ADR-085 D24 of TKT-556

TKT-559 delivery uses a local `stopped` terminal tag with send/decision checkpoint, stop reason and
request-progress fields. Both the store writer and record decoder admit only pre-send stopped
refusals. The record format stays 1 and database version stays 3. The frozen TKT-558 decoder rejects
new stopped rows with a storage warning and excludes them from its queue. Refresh old tabs.
Publication ends the submission; the page coordinator continues the same saved decision independently.
If the opening deadline wins during a pending mark, publish O-LA at once, then retain committed ACT
or write TERM after an abort. A later 401 cannot clear pairing after this result. If an unknown
revocation lookup's deadline wins first, L01 stays final; a listed answer observed first, even late
with its timer withheld, selects V03. Clock-reader exceptions preserve known denial, accepted-body
and revocation knowledge. Host strict-commit observations are recorded in
`docs/sprints/S-2/evidence/TKT-559-strict-commits.json`. They do not replace TKT-560 qualification.

Delivery status: status-before-body classification and the ADR-085 D24 of TKT-556 status set: ticket 2 for Entry, with the Access 503 producer from ticket 0; time checks: ticket 3; Exit copy: ticket 4. **Partial delivery:** TKT-558 implements Entry/storage; TKT-559 implements Entry timing and stalled-body deadlines. TKT-399 implements Exit.

TKT-559 delivers the Entry time behavior in this section, including stalled-body R17/U02 deadlines. TKT-558 supplied truncated/invalid-body classification and status-first knowledge. TKT-399 implements the ticket 4 Exit time behavior.

The send limit is strictly less than 3000 ms from submission or code detection. Check before mint and after mint immediately before live send. A refusal must pass both checks before its queue decision. The opening/offline decision limit is strictly less than 30000 ms from the same start. Check after the accepted answer, after the completed actuation reservation, and immediately before an offline queue decision. These values come from owner history ADR-085 D29 of TKT-399/ADR-085 D30 of TKT-399, not from an imported code constant.

At each check, all four clock readings must be finite, monotonic elapsed time must be nonnegative, each elapsed time must be below the relevant limit, and the elapsed values must differ by at most 1000 ms. These are the B rules, B:`web/scanner/src/scan-clock.ts:43-58`, adopted here as an unmeasured policy assumption. Timers wake the scan; elapsed readings decide. A stalled fetch must wake at the opening deadline as L05. A stalled body uses its retained status: 409/422 stays R17, 200 uses U02, and no generic body error can enter O01. Ignore a later completion for admission purposes after the result latches. An abort does not undo a server write. Clock faults that hide each other are not detectable by these two readings. Physical-device sleep behavior is **not verified**.

Classify status before reading a body, ADR-085 D15 of TKT-556. On 401, latch U01 without waiting for JSON. On 409/422, retain the terminal rejection decision immediately. Decode only to enrich that same decision before its operator result is published; this is not a second decision. Bound this reason read by the remaining response deadline. At expiry publish R17 and stop waiting. A reason arriving after publication is diagnostic only, Z01. Malformed or stalled denial bodies use R17, never O02. A valid unknown reason remains terminal. This corrects M's body-first call and general fallback, `web/scanner/src/App.tsx:323-366`; the decoder can throw for denial bodies at `web/scanner/src/access-contract.ts:79-87`.

Owner ADR-085 D13-1 of TKT-556 accepts terminal live 401 and 409/422 with unreadable bodies. Clear only the captured pairing if it is still current. The scan-route 401 is produced by the request validator before the handler, `services/access/internal/api/server.go:182-193`. Before TKT-557, main mapped every device lookup error, including a DB outage, to that 401. Ticket 0 (TKT-557) splits unknown/revoked as 401, classified lookup availability as pre-decision 503, and other lookup errors as pre-decision 500 on S/R/F. The 503/500 keep pairing. Neither lookup error reaches Touch or a scan handler. That proves 0 only for this HTTP request. U01 and lookup 500/503 retain occurrence U because an earlier transparent attempt is not excluded, P13. Nil device store and unknown auth scheme stay 401 without lookup. Cost: this HTTP request has no Access scan record; a token-expiry window requires re-pairing and a fresh presentation. Keep older committed offline facts for authenticated sync. M already keeps that sync queue on 401, `web/scanner/src/App.tsx:475-479`.

For 200, decode the accepted contract. A malformed or stalled body uses U02, with no admission instruction. For 502/503/504, use the unchanged O02 rule if the minted scan is in time and current. Section 2.4 states the audited producers and Compose-only ADR premise. No Access response at that producer, or a proved Access pre-decision result for this HTTP request, supports that premise; it excludes no earlier attempt for the occurrence. Owner ADR-085 D40 of TKT-556 accepts that the fixed client selects O02 for any 502/503/504, with U, because it cannot distinguish an external proxy from the gateway and has no provenance switch. ADR-025 states the Compose-only topology as a premise; any intermediary before the gateway needs a new ADR and qualification first. Owner ADR-085 D40 of TKT-556 settled this alignment. A missing decision body alone proves no provenance. For 500, 501, and 505-599, ignore the body for permission and use terminal U03 with `unconfirmed_server_error`. Entry copy is "Outcome unknown. Do not admit. Contact an operator." Exit copy is "Exit result unknown; the holder may leave". ADR-085 D36 of TKT-556 amends ADR-085 D24 of TKT-556 because a sent request may already have committed. This offline choice can record an attempted admission even if Access had decided or committed before the error. Reconciliation does not re-decide permission, E9. For 3xx and every other status, use U03 with no admission instruction. Do not follow a redirect as another scan request; request handling must expose redirects or opaque responses to U03. Browser behavior for this policy is **not verified**. The cost of U02/U03 is operator intervention and a possible Access record without opening, rather than an unproved offline instruction. Compared with main's generic queue fallback, U02/U03 and terminal 500 can stop a valid holder and leave no local admission fact. A 500 after an unknown commit, or after the validator replaces a drifted accepted 200, can leave an Access admission without scanner opening, residual A. O01 and gateway 502 can follow commit because the producer received no Access response; O02 keeps U. Any intermediary before the gateway needs a new ADR and qualification before deployment; the bundle does not enforce qualification by status. Ticket 0 includes the device-lookup split as well as narrow live read/begin availability classification. Only that complete change supplies the production pre-decision outage path before or with ticket 2. There is no general claim that main never regresses; terminal ambiguous errors can still stop a valid holder. Staff can force offline by cutting the network, a known workaround, not a safety guarantee. Do not depend on that workaround to claim the status split preserves main's availability.

A decoded acceptance carries `replay=true` or `replay=false/absent`. The own-row CAS independently says whether this call committed the mark. CAS true plus observed complete, valid time, and current session gives A01 even when the connection closes. CAS false plus replay true gives D01/O-D only for this page's own existing ACT; missing, foreign, or ineligible rows give D02/O-G with A+D. CAS false without replay gives G01, A+D. A mark error never becomes offline permission. An existing ACT mark is retained even if the response was not a replay. Once any final local result is latched, a later response is Z01 and changes neither the UI nor queue eligibility.

For an offline result, record the queue decision in the coordinator and issue its UI instruction in the same synchronous decision step, before any queue write. A queue write that completes late does not change that in-time decision. Do not revoke a published QUEUED fact later because its repair was slow. Owner ADR-085 D14-1 of TKT-556 confirmed this reading. TKT-399 history ADR-085 D33 of TKT-399 explains its origin; an audit is not owner authorization. "Never tells staff to admit after the limit" means no new admission decision at or after it. It does not mean that a valid earlier result must disappear when the clock crosses 30 s.

The UI must check time and generation at the point it publishes an admission result, not merely before scheduling React work. Use a synchronous publication step for the scan result, with no intervening await, then start persistence. Test the DOM boundary in the App tier and in Chrome. Browser paint, staff action, and physical hardware are not a real-time clock guarantee; that stronger claim is **not verified**. Do not call a scheduled state update proof that a person saw the instruction before a deadline.

#### 3.3 Reading the six failure columns

- **S**: the requested outcome transaction commits. For a no-write outcome, no write is needed.
- **F**: that outcome transaction aborts. Mint is assumed committed unless the row explicitly says mint failed. Synchronous throw and asynchronous abort must both be tested.
- **C**: the connection closes or is replaced while the scan waits. Its existing transaction may commit or abort. The cell states both where needed. The page and its coordinator stay alive.
- **T**: another tab is open. This includes a compatible tab and the old-tab barrier. The lock remains held even beyond lease expiry. Apply F as well if the local outcome write fails.
- **V**: a version change first attempts pending repair writes on the still-open connection, then closes it after the attempts settle, ADR-085 D27 of TKT-556. The upgrade waits. Failure leaves the same protected PENDING while live and P on reload if the repair did not commit before page loss. Compatible future code must keep the protocol. Old code is barred by section 7. A database deletion is data loss, outside ordinary version upgrade; it must not be described as preserved storage.
- **P**: actual page loss, before or after the outcome write. The cell states both results. A committed row survives unless storage itself is deleted. No result is newly shown after page loss.

A slash separates alternatives controlled by transaction completion, not an implementation choice. `never` means never in this live-page execution. Only a cell that explicitly contains P admits the page-loss exception. `Q-fact` is an entry/exit admission fact as defined by Access, E9. `Q-refusal` is only `local_decision`, E8. `PEND` means PENDING, `TERM` means RESOLVED, and `ACT` means ACTUATED. All new queue rows carry the tagged outcome. T and V cells assume the section-7 barrier has been delivered. A combined E/X row defines two separate row addresses, such as A01-E and A01-X. In every P cell, "no new UI" applies to the lost page. A reloaded compatible page must show O-W for recovered new-format PENDING rows under ADR-085 D13-4 of TKT-556 and section 2.3. This notice does not claim passage or authorize admission.
