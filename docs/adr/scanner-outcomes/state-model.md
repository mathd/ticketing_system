# ADR-085 part 2: Actors, fields, and states

Part of the accepted [scanner outcome decision](../ADR-085-scanner-local-outcome-model.md).
Read its status and scope before using this part. Original evidence and delivery-plan claims
remain bound to their stated baselines; operator behavior is in the [scanner runbook](../../runbooks/scanner.md).

### 2. Actors, fields, and states

#### 2.1 Actors and ownership, D2 and D3

Delivery status: implemented by TKT-558. The page coordinator and page-owner lock outlive database connections and React cleanup.

Use one page coordinator for the life of the JavaScript page. It owns the local decisions and one page-owner browser lock. Acquire that lock before the first mint. A database connection borrows the coordinator; it does not own the lock. Store replacement reuses the same page owner and coordinator. It never calls the current owner-replacement recovery path for its own live scans.

Keep the lock for the page's life. This is deliberately simpler than releasing it for each outcome. A connection close, React unmount, pairing reset, and version change do not release it. The page can close every database connection and still retain its decisions. A component remount must reuse the page coordinator. Actual page loss removes the coordinator and the browser lock. A bfcache or suspension case must be tested in the browser before any claim about it; behavior there is **not verified**.

The coordinator records an occurrence id before its mint transaction starts. If that transaction aborts, remove the unwritten occurrence from its registry. A connection close during a transaction does not prove abort. Wait for transaction completion or abort before deciding whether a row exists. Do not erase an entry merely because its connection closed.

| Actor | Authority and limit |
|---|---|
| Page and scan controller | Capture the credential, direction, pairing generation, start readings, and occurrence id. Make one final local decision. Retain it before an outcome write starts. |
| Coordinator | Keep the live page's decisions through every connection replacement. Retry the same write through a compatible connection. Never reclassify a decided row because a write failed. |
| IndexedDB connection and transactions | Store facts and final decisions atomically. Transaction completion, rather than request success, permits send or opening. Connection closure stops new operations; it does not imply page loss. |
| Browser owner lock | Prevent every honest tab from recovering this page's PENDING rows while the page lives. Use the same owner-lock name across database versions. No optional coordinator path in production. |
| Lease | Renew PENDING leases every 10 s with a 30 s expiry when storage works, retaining the current ADR values. An expired lease alone never proves death. A true reload may bypass lease expiry only after it acquires the old owner's absent lock. |
| Other compatible tab | May send a committed QUEUED fact. Cannot actuate it, alter its direction, or recover a live owner's PENDING row. Concurrent sync retries reuse one occurrence id. |
| Old tab | Cannot be trusted to read new fields. The storage barrier in section 7 must keep all new-protocol rows out of its reader. |
| Sync | Reads only committed QUEUED rows. Repairs of this page's failed writes run separately. Sync never decides admission and never opens a gate. |
| Access | Decides live scans. Records submitted queue facts or local refusals. It cannot infer an unsubmitted local decision. E8-E10 define its current boundary. |

The scope is honest scanner code and storage failures. This is not containment of a compromised same-origin page, a scanner under attacker control, or a database writer. ADR-021's trust boundary remains unchanged, `docs/adr/ADR-021-ticket-lifecycle-trail-integrity.md:163-186`.

#### 2.2 Durable record, D4

Delivery status: ticket 2 for `recordFormat`, `localOutcome`, `decidedAt`, explicit Entry direction and the typed refusal variant; ticket 4 for Exit direction. **Partial delivery:** TKT-558 implements Entry/storage; TKT-559 implements Entry timing and stalled-body deadlines. TKT-399 implements Exit.

Keep the existing immutable fields `occurrenceId`, `qrPayload`, `occurredAt`, and `createdAt`. Keep `ownerId` on every new PENDING row. Keep `leaseExpiresAt` as advisory recovery time. These names exist on M, E1. Add a required `direction` for every new normal scan, as B does at B:`web/scanner/src/occurrences.ts:559-572`. A local refusal is a distinct record variant with `localDecision='revocation_refused'` and no direction. It is entry-only. Do not put an exit into that variant.

TKT-558 adds three durable fields. The fields are `recordFormat`, with value 1 for new records and 0 for explicitly classified legacy records; `localOutcome`, a tagged local decision with its reason or cause; and `decidedAt`, the device-claimed decision timestamp. The coordinator keeps the same decision in memory before the write. Store the start clock readings in the live scan context. They are not durable evidence of elapsed time after reload. Keep `actuated` for compatibility, but document it as an actuation reservation. It does not prove physical passage.

| Durable state | Required meaning and eligibility |
|---|---|
| PENDING | Mint committed; no final outcome is committed yet. Never listed for sync while its owner lives. A page decision may already exist in memory if its write failed. |
| ACTUATED | The own-row, never-actuated compare-and-set committed an actuation reservation. Never listed for reconciliation. It does not prove the gate opened. |
| QUEUED | A queue decision committed with `localOutcome`. A normal live attempt reaches it only when the producer received no Access response, or Access proved a pre-decision origin, using the exact D24 status set or classified transport failure. Local refusal and dead-page recovery are separate transitions. D31 preserves pre-upgrade QUEUED rows even when main queued a known denial or live 401; new rows cannot use that exception. Eligible for sync. |
| SYNCED | A valid reconcile response said `recorded` or `synced`. Terminal. Never actuates. |
| RESOLVED | A live rejection, definitive live 401, stopped scan, unclassified local failure, unconfirmed status/body, local actuation failure, or reconcile `conflict`/`rejected`. Terminal. Never enters the queue again. |

The local outcome tag has three families: queue, terminal, and actuation reservation. Queue records state whether the cause was classified transport failure, a proven pre-decision Access status or verified no-Access-response producer, a local refusal, or uncertain dead-page recovery. Terminal records keep the exact live rejection reason or unknown rejection reason, HTTP-authentication refusal, unconfirmed response status, stopped checkpoint and send status, unclassified local exception, local mark failure, cancellation, or reconcile failure. Actuation records keep the reservation and may add a no-opening/late annotation after the mark. TKT-558 implements the untimed Entry tags in `occurrence-model.ts`. TKT-559 adds Entry stopped checkpoints. TKT-399 delivers Exit annotations. They are not sent as new Access event fields. Keep the existing `result` for a validated reconcile result; do not overwrite the local decision with that result. `decidedAt` exists only when the page actually made that decision. Recovery must not invent an original decision time: leave it absent for uncertain recovery, with the uncertainty in the outcome tag.

Retain these five existing state names instead of introducing many independent booleans. The tagged outcome distinguishes why a terminal row exists. Validate state/outcome combinations at the production store boundary. A legacy row without the new outcome remains readable under the explicit legacy rules in section 7. A new-protocol decided row missing its required outcome is corrupt, not a legacy admission. PENDING legitimately has no durable final outcome. On the v2-to-v3 upgrade, stamp existing rows as legacy without changing their id, credential, time, state, or refusal tag. A missing format marker outside that migration is not permission to guess legacy. An unrecognized format stays local with a storage warning. Format numbering is separate from the IndexedDB version.

The coordinator has these conceptual states, **new design labels, not code symbols**:

1. WAITING. The mint or live answer is not final. Owner lock held. Retain the current knowledge class from section 2.4; no exception is permission to queue.
2. MARKING. Access accepted; the one atomic actuation reservation is in progress. Owner lock held. Sync cannot see the row.
3. QUEUE-DECIDED. An in-time offline fact or local refusal is final. A failed queue write leaves PENDING protected. Retry QUEUED only.
4. TERMINAL-DECIDED. A rejection, definitive 401, unconfirmed status/body, late scan, or local failure is final. A failed terminal write leaves PENDING protected. Retry RESOLVED only.
5. ACTUATION-DECIDED. The mark committed. Check time and generation before issuing the single opening instruction. A late check leaves ACTUATED and no opening.

After its final state commits, the coordinator can remove that occurrence from its repair registry. Keep the scan completion latch until all callbacks are cancelled or have settled. The one page-owner lock remains held. This bounds repair memory by unsettled work rather than all scans since load.

No generic "decided, release for recovery" operation exists. Once final, the decision cannot change to queue after an exception. In particular, do not copy B's rejection release, E11. A diagnostic failure is separate from an admission instruction.

#### 2.3 Allowed transitions and repair

Delivery status: TKT-558 implements the Entry transitions, repair, page-loss recovery and durable recovery notices. TKT-559 supplies Entry time checks; TKT-399 delivers Exit behavior.

- Mint normal scans and refusals as owned PENDING. A local refusal must not be born QUEUED before its time check. This changes ADR-066 section 8 and `web/scanner/src/occurrences.ts:270-281`; D18 records the deviation and section 8 ticket 1 owns the ADR amendment.
- PENDING can become QUEUED only with a matching coordinator queue decision, or through the explicit page-loss recovery exception below.
- PENDING can become ACTUATED only in one owner-matching, never-actuated, normal-scan transaction. A local refusal, terminal decision, or queue decision cannot actuate.
- PENDING can become RESOLVED only with the matching final terminal decision. Rejection and lateness are terminal even if the transaction fails.
- QUEUED can become SYNCED or RESOLVED only from a validated response for that exact submitted id. No UI copy from sync instructs admission.
- ACTUATED, SYNCED, and RESOLVED never become QUEUED. No stale callback may overwrite them. A late annotation can enrich ACTUATED but cannot clear its mark.
- An operation that finds no matching owned row reports no change. It must not claim a successful terminal write. A replacement store cannot recreate a missing row as an admission. Keep the warning and require operator action if the row disappeared.
- On version change, attempt pending final-write repairs on the still-open connection before `close()`, D27. Keep each in-flight mint/mark transaction's completion evidence. Settle those transactions before choosing any dependent repair; do not overwrite a committed ACT. Start and observe the required repair transactions before closing. The upgrade waits for these transactions and the old connection; no immediate-upgrade bound is claimed. A failed repair keeps the same live-page decision and owner lock, but leaves P if the page is later lost with only PENDING durable. Always close after repair attempts settle, including aborts; do not wait for a replacement connection to repair before closing the old one.
- Run retries at storage recovery and queue refresh, with at most one repair per occurrence at a time. A failed retry stays protected; it must not block unrelated committed queue rows. Do not spin on an unreadable store. Show a storage warning and allow an explicit retry.

After actual page loss, a compatible tab may recover a new-format still-PENDING row once the owner lock is absent and the lease or genuine-reload condition allows it. Preserve credential, id, timestamp, direction, and refusal type. Store the local cause as `uncertain_recovery`; leave original `decidedAt` absent. This local label is not sent as a new Access field. Access records a normal recovered row as an ordinary admission fact, with the same replay, policy, and integrity handling as any submitted fact, `services/access/internal/store/reconcile.go:192-260`. Access does not know whether the lost page ever instructed staff to admit.

Two cases need separate authority. A failed terminal write followed by page loss is TKT-399 D30's stated residual. A crash or reload while WAITING, with no final decision yet, follows ADR-025 section 3's existing interrupted-request recovery, `docs/adr/ADR-025-admission-events-and-offline-reconciliation.md:202-209`. Owner D13-4 now accepts that case on condition that the reloaded page shows the recovered scan or scans. W01 defines it. Even an unsent attempt can become an ordinary admission in Access. A known denial, late decision, or local failure lost from memory can also become a false fact. No local label makes that server fact uncertain to Access.

Every compatible page must render all unacknowledged recovery notices, whichever page recovered or synced the row, ADR-085 D28. Read this durable notice list at startup and recovery/queue refresh, without a current-owner filter. This includes a second tab that recovers and syncs the row before any reload. The next page still shows O-W. List each recovered id, claimed scan time, direction or refusal type, local recovery cause, and sync state. State that the prior result and physical passage are unknown. Do not show an admission instruction or retry actuation. Preserve a local recovery-notice marker through queue retirement and reload until the operator acknowledges it. Acknowledgement clears the notice, not the fact. If the notice cannot be committed, do not queue that recovery yet; show a storage warning and retry. Test the committed row and notice together so automatic sync cannot erase the evidence before rendering. No new server endpoint is needed. TKT-558 implements and tests the Entry notice mechanism. Physical passage remains unknown.

TKT-558 D22 permits one guarded reason-only RESOLVED-to-RESOLVED enrichment. It requires the
same owner, occurrence, refusal status, latch ID and decision time, and an unknown stored reason.
It cannot change queue eligibility or the local outcome family. The durable reason can remain
unknown after a failed enrichment. The memory result can be published while either write is pending.

#### 2.4 Client knowledge is an independent axis, D15-D17

Delivery status: TKT-558 implements Entry status-before-body classification. TKT-557 supplies the Access producers. Deadlines and late branches remain in ticket 3; TKT-399 delivers Exit behavior.

Each table row is the product of client knowledge, local row/transaction evidence, decision latch, direction, time/session, and failure column. A server outcome name alone cannot select a row. The coordinator keeps the known status before it reads a body. It keeps accepted/replay knowledge apart from CAS evidence. A body-read error must not erase a known denial status.

#### 2.4a Producer-by-layer matrix, D33

Delivery status: TKT-557 supplies the Access producers. TKT-558 implements the Entry browser adapter and scanner-local rules. TKT-559 supplies Entry timing; TKT-399 delivers Exit behavior. The Compose-only premise remains binding.

This matrix records the code-path evidence of the TKT-556 producer audit, including the browser network stack layer. It has 11 layer rows and 17 columns, including the layer column. S means live `POST /scans`, R means `POST /scans/reconciliations`, and F means `GET /scans/voided-tickets`. Each cell names an origin or says `cannot produce` with an evidence key. Passing an upstream result does not make a layer its origin. The keys below give file:line evidence. Proposed changes are requirements, not executed evidence.

The producer audit is an ADR premise for the supported topology. A live normal attempt uses O01 for a classified no-response transport failure and the unchanged O02 rule for exactly 502/503/504, with the existing time/session conditions. In the inspected Compose route, audited producers either received no Access response or prove a pre-decision origin for this HTTP request. A status or missing body does not prove provenance. O01/O02 retain occurrence U.

ADR-025 states the Compose-only topology as a premise of D24 fallback, through this amendment and its §3 note. `compose.yaml:585-614` exposes the gateway and routes it directly to Access. `web/scanner/src/App.tsx:45-48` uses fixed relative URLs; `web/scanner/vite.config.ts:1-13` has no provenance switch. The proposed classifier cannot distinguish external 502/503/504 from the same status in this topology. The client would still select O02, with U, if an intermediary returned one. It would not select U03 while qualification was pending. Adding any intermediary before the gateway requires a new ADR and qualification before deployment. No switch ticket is proposed. Owner D40 accepts this fixed-client rule and supersedes revision 3's unknown-origin terminal U03/disabled-fallback proposal and D33's external-proxy clause.

Owner D40 settles the External proxy row and K8: any 502/503/504 selects O02 with occurrence U under the existing time/session conditions; an external proxy is outside the Compose-only premise, and any intermediary before the gateway requires a new ADR and qualification first.
